Zero-Knowledge Architecture

Decentralized P2P File Transfer

FreeHole enables wire-speed, end-to-end encrypted file sharing directly between peers using WebRTC DataChannels and decentralized IPFS Relays.

Direct P2P Streaming WebRTC

Files stream directly from sender to receiver via encrypted WebRTC DataChannels without intermediaries or central servers.

  • ✓ Direct Peer-to-Peer: Maximum transfer speed bounded only by peer connections.
  • ✓ No Cloud Storage: Data flows memory-to-memory between browsers.

IPFS Decentralized Relay Async

Staging relay support for asynchronous transfers and difficult NAT / firewall traversal using decentralized IPFS pinning.

  • ✓ Asynchronous Pickup: Receiver does not need to be online at the exact same second.
  • ✓ Zero Plaintext Storage: Only AES-256 encrypted ciphertext blocks are relayed.

Universal Interoperability Web & CLI

Seamless cross-platform file transfers: send files from terminal CLI via wh send <file> and receive inside this web app.

  • ✓ Cross-Platform: Terminal-to-Browser, Browser-to-Terminal, or Browser-to-Browser.
  • ✓ Lightweight Core: Pure WebRTC & decentralized rendezvous protocols.

End-to-End Encryption AES-GCM

All files are encrypted client-side using AES-GCM (256-bit) with PBKDF2 key derivation and chunk-index binding.

  • ✓ Zero-Knowledge Mnemonic: The code is both the rendezvous address and the secret key.
  • ✓ Confidentiality: Relays and signaling peers never inspect plaintext or metadata.

How FreeHole P2P Works

01

Local Encryption

Sender generates mnemonic code and encrypts file via AES-256-GCM in the browser or terminal.

02

P2P Signaling

Peers exchange WebRTC handshake offers via decentralized zero-knowledge rendezvous.

03

Direct Stream

Encrypted binary chunks stream directly between connected peers over WebRTC DataChannels.

04

Local Decryption

Receiver decrypts chunks in-memory using derived AES-256 key and triggers file download.

Zero-Knowledge Architecture

Decentralized Sovereign File Transfer

FreeHole enables fast, end-to-end encrypted file sharing using Freenet WASM Contracts, content-addressed Blake3 Chunks, and sovereign storage.

Freenet Sovereign Storage Default

Files are sliced into verifiable 128KB chunks, addressed by cryptographic Blake3 hashes, and stored across sovereign Freenet peer nodes.

  • ✓ Immutable & Verifiable: Every chunk verified via Blake3 digest before reassembly.
  • ✓ No Central Servers: Stored across peer nodes without single points of failure.

WASM Channel Contract CRDT

The wormhole-channel WASM contract coordinates transfer manifests on Freenet with join-semilattice merge laws, ensuring robust state sync.

  • ✓ Lightweight State Sync: Encrypted manifest metadata coordinated safely on Freenet.
  • ✓ Deterministic Consensus: State updates validated by contract verification rules.

Universal Interoperability Web & CLI

Seamless cross-platform file transfers: send files from the CLI via wh send --freenet and download inside the Web App, or vice-versa.

  • ✓ CLI + Web Gateway: Native integration with Freenet local node on port 7509.
  • ✓ Sandboxed Container: Safe execution inside Freenet Web Container.

End-to-End Encryption AES-GCM

All files are encrypted client-side using AES-GCM (256-bit) with PBKDF2 key derivation and chunk-index binding.

  • ✓ Zero-Knowledge Mnemonic: The code is both the rendezvous address and the secret key.
  • ✓ Confidentiality: Network peers and relays never inspect plaintext or metadata.

How FreeHole Works on Freenet

01

Local Encryption

Sender generates mnemonic code and encrypts file via AES-256-GCM in the browser or terminal.

02

Freenet Publishing

Sender publishes 128KB Blake3 chunks to Freenet storage and registers the manifest on the channel contract.

03

Decentralized Sync

Receiver inputs code. Peers resolve manifest state from Freenet contract and fetch verifiable chunks.

04

Local Decryption

Receiver verifies each chunk via Blake3, decrypts in memory via AES-256-GCM, and reassembles the file.

FreeHole CLI (wh)

The CLI binary is named wh to avoid collisions with magic-wormhole. Fast, lightweight, and sharing the exact universal core with the browser dashboard.

Global Installation npm / git

CLI Command Reference

Command Description Action
wh send <file> Encrypts (AES-256-GCM) and initiates direct WebRTC P2P stream between terminals or browsers.
wh receive <code> Connects to sender via sync code, receives chunks, and decrypts the file locally.
wh send <file> --ipfs Uploads encrypted chunks to IPFS relay for asynchronous transfer between nodes.
wh list Lists active transfers stored locally.

Practical Usage Examples

1. CLI Sender → Web App Receiver

Send from terminal and receive in this browser:

wh send document.pdf

Paste the generated sync code (e.g. 82-gentle-bird) into the Receive File tab above to start downloading in the browser.

2. Web App Sender → CLI Receiver

Drag a file into the "Send File" tab in the browser, then download from terminal anywhere:

wh receive 82-gentle-bird

The terminal connects directly via P2P and decrypts the file instantly.
